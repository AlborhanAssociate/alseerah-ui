# السيرة ai — واجهات المنصّة

واجهات الهبوط والدخول والمحادثة لمنصّة «السيرة ai»، مبنيّة بـ Vite وReact 19 وTypeScript وTailwind CSS 3.4 وlucide-react، بالعربيّة واتّجاه RTL، وبنمطَين فاتحٍ وداكن.

## المتطلّبات

| الأداة | النسخة |
|---|---|
| Node.js | 22 فأعلى (يُستعمل `WebSocket` المدمج وميزات ES2023) |
| npm | 10 فأعلى، يأتي مع Node |

لا حاجة إلى قاعدة بيانات ولا خادم؛ الواجهات تعمل على بياناتٍ نموذجيّة محلّيّة إلى أن تُربط بالخادم.

## التثبيت والتشغيل

```bash
git clone https://github.com/AlborhanAssociate/alseerah-ui.git
cd alseerah-ui
npm ci
npm run dev
```

ثمّ افتح `http://localhost:5173`. خادم التطوير يُحدّث الصفحة تلقائيّاً عند كلّ تعديل.

> إن ظهر خطأ صلاحيّات في ذاكرة npm على macOS، شغّل الأوامر مع `--cache /tmp/npm-cache`.

## الأوامر

| الأمر | ما يفعله |
|---|---|
| `npm run dev` | خادم التطوير على المنفذ 5173 |
| `npm run build` | بناء الإنتاج في مجلّد `dist/` مع فحص الأنواع |
| `npm run preview` | تشغيل ما بُني محلّيّاً للمراجعة قبل النشر |
| `npx tsc -p tsconfig.app.json --noEmit` | فحص الأنواع وحده |

## المسارات

| المسار | الشاشة |
|---|---|
| `/` | الهبوط (شاشة واحدة على نسق البينتو) |

## الدخول التجريبيّ

لا يوجد خادم مصادقة في هذه النسخة. أيّ بريدٍ صحيح الصيغة وكلمة مرورٍ من ثمانية أحرفٍ فأكثر يفتحان المحادثة، وتُحفظ الجلسة في `localStorage` تحت المفتاح `alseerah.session`. المنطق كلّه في `src/auth/session.ts` ويُستبدل بنداءات الخادم عند الربط.

## النشر

المشروع تطبيق صفحةٍ واحدة يُبنى إلى ملفّاتٍ ثابتة في `dist/`، ويصلح لأيّ مضيفٍ ثابت.

- **مسار النشر**: إن نُشر تحت مسارٍ فرعيّ (مثل `https://example.org/alseerah-ui/`) يُضبط المتغيّر `VITE_BASE` قبل البناء:

  ```bash
  VITE_BASE=/alseerah-ui/ npm run build
  ```

  عند النشر على جذر الدومين لا يلزم شيء.

- **إعادة التوجيه**: على المضيفات الثابتة يجب إرجاع `index.html` لأيّ مسارٍ مجهول حتّى تعمل الروابط المباشرة. سير العمل في `.github/workflows/pages.yml` يفعل ذلك بنسخ `index.html` إلى `404.html`.

- **GitHub Pages**: سير العمل المرفق يبني وينشر آليّاً عند كلّ دفعٍ إلى `main`. يتطلّب أن يكون المستودع عامّاً أو أن تكون المنظّمة على خطّةٍ مدفوعة.

## بنية المشروع

```
src/
  pages/            الشاشات: LandingOnePage، LandingPage (السابق)، LoginPage، LegalPage
  components/
    one/            بطاقات الهبوط ونوافذه ونصوصه (content.ts)
    chat/           المحادثة: ChatScreen وحده يعرف البيانات، والباقي مكوّنات صامتة
    home/           أقسام الهبوط السابق
    ui/             الصورة الرمزيّة، زرّ النمط، عناصر أوّليّة
    brand/          الشعار الحيّ
  auth/session.ts   الجلسة المحلّيّة المؤقّتة
  data/             بيانات نموذجيّة تُستبدل عند الربط
  types.ts          الأنواع، مطابقة لما يُرجعه /api/v1/chat
  theme.ts          النمط الفاتح والداكن على جذر الوثيقة
  index.css         متغيّرات الألوان للنمطَين ومكوّنات CSS الصغيرة
tailwind.config.js  الرموز: الألوان والزوايا والظلال ومتغيّر light
public/             الشعارات والصور؛ الصور المؤقّتة في public/tmp مع مصادرها في CREDITS.md
```

## الربط بالخادم

نقاط الربط الثلاث، بالترتيب:

1. `src/components/chat/ChatScreen.tsx`: استبدال `src/data/conversation.ts` بنداءات `/api/v1`. الأنواع في `src/types.ts` جاهزة.
2. `src/auth/session.ts`: استبدال `signIn/signOut` بمصادقة الخادم، والاسم من ملفّ المستخدم.
3. `src/lib/pendingQuestion.ts`: السؤال المكتوب في الهبوط يُستهلك في `ChatScreen` عند الفتح؛ يُستبدل السطران بنداء الإرسال الحقيقيّ.
